## Эпик #1 — Требования к логину [ToDo]

- Трекер: TestCase (замечание: у issue с требованиями установлен трекер TestCase)
- Проект: Страница логина · Приоритет: Major · Статус: ToDo · 0%
- Дочерние: #2–#12

### Описание (оригинал)

1. Общее описание
Необходимо реализовать страницу входа в систему для пользователей. Страница должна быть современной, удобной и безопасной.

2. Функциональные требования

2.1. Поля ввода. На странице должны быть поля для ввода логина (или email) и пароля. Пароль должен скрываться звездочками.

2.2. Кнопка "Войти". При нажатии на кнопку система отправляет данные на сервер и, если всё верно, перенаправляет пользователя на главную страницу.

2.3. Восстановление пароля. Под кнопкой входа должна быть ссылка «Забыли пароль?». При нажатии на неё открывается страница сброса пароля.

2.4. Обработка ошибок. Если пользователь ввел неверные данные, система должна показать сообщение об ошибке. Ошибки нужно выводить красным цветом.

2.5. Капча. Для защиты от ботов после 3 неудачных попыток ввода нужно показывать капчу.

3. Нефункциональные требования (NFR)

3.1. Производительность. Страница должна загружаться очень быстро, чтобы пользователи не уходили.

3.2. Браузеры. Поддержка всех популярных браузеров (Chrome, Safari, Firefox, Edge).

3.3. Мобильная версия. Интерфейс должен быть адаптивным (Mobile First).

4. Ограничения

4.1. Блокировка. Если пользователь вводит неверный пароль 5 раз подряд, аккаунт должен быть заблокирован на 15 минут.

4.2. Запомнить меня. Галочка «Запомнить меня» должна сохранять сессию на 30 дней.

5. Интеграции

Система должна поддерживать вход через SSO (Google, Yandex).

### #5 — REQ-2.2 — Кнопка «Войти» [ToDo]

```
## requirement_id: REQ-2.2

### Описание
Реализовать кнопку «Войти» на странице логина.

### Acceptance Criteria
1. Кнопка «Войти» отображается под полями ввода логина и пароля
2. Кнопка имеет состояния:
   - Disabled: кнопка неактивна, пока не заполнены обязательные поля
   - Default: активное состояние для отправки формы
   - Loading: индикация загрузки после нажатия (спиннер/анимация) с блокировкой повторной отправки
3. При нажатии на кнопку выполняется POST-запрос на endpoint аутентификации
4. При успешном входе пользователь перенаправляется на главную страницу (URL уточняется)
5. При ошибке отображается соответствующее сообщение об ошибке
6. Кнопка не позволяет повторную отправку до получения ответа от сервера
```

### #7 — REQ-5 — SSO интеграции [ToDo]

```
## requirement_id: REQ-5

### Описание
Реализовать вход через сторонние сервисы (SSO).

### Acceptance Criteria
1. На странице логина отображаются кнопки входа через SSO-провайдеров:
   - Google
   - Yandex
   - VK
2. Используемый протокол: OAuth 2.0 / OIDC
3. После авторизации через SSO пользователь перенаправляется на главную страницу
4. При первой авторизации через SSO создаётся локальная учётная запись (если не существует)
5. Привязка SSO-аккаунта к существующей учётной записи по email
6. Обработка ошибок SSO:
   - Отказ пользователя в авторизации → возврат на страницу логина
   - Ошибка провайдера → отображение сообщения об ошибке
   - Истечение токена → повторная авторизация
7. Кнопки SSO располагаются под основной формой входа
```

### #8 — REQ-2.5 — Капча (защита от ботов) [ToDo]

```
## requirement_id: REQ-2.5

### Описание
Реализовать капчу после N неудачных попыток входа.

### Acceptance Criteria
1. После 3 неудачных попыток входа подряд отображается капча
2. Тип капчи: reCAPTCHA v2 (галочка "Я не робот") или Cloudflare Turnstile (требует уточнения)
3. Капча отображается перед/вместе с кнопкой «Войти»
4. Счётчик неудачных попыток сбрасывается после успешного входа
5. Счётчик неудачных попыток привязан к IP-адресу и/или сессии
6. Капча не отображается при первом входе или при первой попытке после успешного входа
```

### #9 — REQ-4.2 — Функция «Запомнить меня» [ToDo]

```
## requirement_id: REQ-4.2

### Описание
Реализовать опцию «Запомнить меня» на странице логина.

### Acceptance Criteria
1. Чекбокс «Запомнить меня» отображается под полями ввода, над кнопкой «Войти»
2. При включённой опции сессия сохраняется дольше (например, 30 дней)
3. Механизм сохранения: cookie с refresh token (JWT или аналогичный)
4. При выключенной опции сессия действует только до закрытия браузера (session cookie)
5. Безопасность: токен «Запомнить меня» хранится только в httpOnly cookie
6. Опция «Запомнить меня» не отключает капчу и не обходит блокировку
7. При блокировке аккаунта токен «Запомнить меня» аннулируется
```

### #11 — REQ-4.1 — Блокировка после N неудачных попыток [ToDo]

```
## requirement_id: REQ-4.1

### Описание
Реализовать блокировку входа после 5 неудачных попыток подряд.

### Acceptance Criteria
1. После 5 неудачных попыток входа подряд учётная запись временно блокируется
2. Интервал отсчёта попыток: 15 минут (5 неудачных попыток в течение 15 минут)
3. Длительность блокировки: 30 минут
4. После блокировки пользователю отображается сообщение: «Аккаунт временно заблокирован. Попробуйте снова через 30 минут.»
5. Счётчик неудачных попыток сбрасывается после успешного входа
6. Счётчик неудачных попыток сбрасывается после истечения временного окна (15 минут)
7. Блокировка не влияет на возможность восстановления пароля
```

> Примечание ingestion: оригинал эпика (#1, п.4.1) — блокировка **на 15 минут**; декомпозиция (#11) — длительность блокировки **30 минут**, а 15 минут трактуется как окно подсчёта попыток. Противоречие фиксировается как есть (самостоятельно не разрешается).
