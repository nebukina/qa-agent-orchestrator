```
# Требования к странице авторизации

1. Форма входа
На странице должны быть два поля: "Email" и "Пароль".
Поле "Email" имеет тип email и обязательную валидацию на наличие символа "@".
Поле "Пароль" имеет тип password (символы скрыты звездочками).
Оба поля обязательны для заполнения.

2. Кнопка "Войти"
При нажатии на кнопку "Войти" данные отправляются POST-запросом на эндпоинт /api/login.
Если сервер возвращает HTTP 200 OK, пользователь перенаправляется на страницу /dashboard.
Если сервер возвращает HTTP 401 Unauthorized, под формой появляется текст красного цвета: "Неверный email или пароль".
Если сервер возвращает HTTP 500 Internal Server Error, появляется текст: "Ошибка сервера. Попробуйте позже".

# Acceptance Criteria (Критерии приемки)

- AC-1: Given пользователь находится на странице входа, When он кликает на поле "Email", Then поле получает фокус ввода.
- AC-2: Given пользователь ввел email без символа "@", When он нажимает "Войти", Then форма не отправляется, появляется системная подсказка браузера о неверном формате email.
- AC-3: Given пользователь ввел валидный email и верный пароль, When он нажимает "Войти", Then происходит перенаправление на /dashboard.
- AC-4: Given пользователь ввел валидный email и неверный пароль, When он нажимает "Войти", Then появляется красный текст "Неверный email или пароль".
- AC-5: Given сервер недоступен (возвращает 500), When пользователь нажимает "Войти", Then появляется текст "Ошибка сервера. Попробуйте позже".
```
