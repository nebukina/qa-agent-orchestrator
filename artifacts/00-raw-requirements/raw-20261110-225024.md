## Описание issue #72 (дословно)

# Требования к странице авторизации (Вход)

1. Форма входа
На странице должны быть два поля: "Email" и "Пароль".
Поле "Email" имеет тип email.
Поле "Пароль" имеет тип password.
Оба поля обязательны для заполнения (атрибут required).

2. Порядок действий при нажатии на кнопку "Войти"
Шаг 1 (Клиентская валидация): При нажатии на кнопку "Войти" браузер сначала проверяет заполненность полей и формат Email. Если поля не заполнены или Email не содержит "@", браузер показывает системную подсказку и ОСТАНАВЛИВАЕТ отправку.
Шаг 2 (Отправка): Если клиентская валидация пройдена, форма отправляет POST-запрос на эндпоинт /api/login.

3. Обработка ответов сервера
Если сервер возвращает HTTP 200 OK, происходит перенаправление на страницу /dashboard.
Если сервер возвращает HTTP 401 Unauthorized, появляется сообщение об ошибке красного цвета: "Неверный email или пароль".
Если сервер возвращает HTTP 500 Internal Server Error, появляется сообщение об ошибке: "Ошибка сервера. Попробуйте позже".

# Acceptance Criteria (Критерии приемки)

- AC-1: Given пользователь ввел валидный email и верный пароль, When он нажимает "Войти", Then происходит перенаправление на /dashboard.
- AC-2: Given пользователь ввел валидный email и неверный пароль, When он нажимает "Войти", Then появляется красный текст "Неверный email или пароль".
- AC-3: Given поле "Email" пустое, When пользователь нажимает "Войти", Then браузер показывает системную подсказку "Заполните это поле", а POST-запрос на сервер НЕ отправляется.
- AC-4: Given сервер недоступен (возвращает 500), When пользователь нажимает "Войти", Then появляется текст "Ошибка сервера. Попробуйте позже".
