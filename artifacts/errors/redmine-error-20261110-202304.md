## Диагностика (отсекает ложные причины)

- **Чтение работает штатно в тот же момент:** `list_projects`, `list_metadata(kind=trackers/priorities/statuses)`, `list_issues`, `get_issue(#72)` — успешны, контрольное чтение выполнено **после** последней неудачной записи и тоже успешно.
- **`list_metadata(kind=me)`** (эндпоинт собственной учётной записи) — отклонён с тем же сообщением → ключ не имеет доступа даже к self-account, характерно для read-only API-ключа.
- Отказ **не зависит** от payload: не помогают ни числовой `project_id`, ни identifier, ни снятие `tracker_id`/`priority_id`, ни минимальный набор полей → причина не в валидации полей, а в отсутствии прав на запись.
- Отказ **не транзитный**: 5 последовательных попыток, идентичный текст ошибки.
- Альтернативного пути записи нет: в каталоге Code Mode единственный инструмент создания issues — `tools.redmine.create_issue`; второй MCP-сервер с правом записи отсутствует.
- **Важно:** ошибка не связана с директивой пользователя о `relations`/`custom_fields` — эти API не вызывались и не проверялись.
