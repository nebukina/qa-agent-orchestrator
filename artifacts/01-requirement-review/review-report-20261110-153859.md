## Приложение G. Ключевые риски (для Оркестратора, вне нумерации проблем)

1. **Молчаливая регрессия норм**: удаления (500+AC-5, «@», блокировка 5/15, восстановление, «под формой», AC на неформат) не зафиксированы ни в одном журнале (GAP-27, CON-02) — команда может не заметить, что требование изменилось; носители прежних редакций уничтожены.
2. **Credential stuffing без защиты**: правило блокировки #65 удалено, rate-limit не задан (GAP-08, GAP-15) — форма входа осталась без анти-переборной нормы.
3. **Разрыв сквозной политики пароля**: регистрация (#69) требует ≥8, вход (#70) молчит, бывший носитель (#65) удалён → сценарий «регистрация → вход» нормативно не замкнут (AMB-02, GAP-23).
4. **Ложные падения AC-2 между средами**: оракул привязан к локализуемой строке браузера (TEST-01) — один и тот же билд «падает» в Safari/Firefox и «проходит» в Chrome-RU; без OQ-09 приёмка AC-2 неконституционна.
5. **Путаница конвейера из-за трекера**: #70 (требования) лежит в трекере TestCase рядом с #69 (требования, Task) — автоматические выборки «все TestCase проекта = тест-активы» примут требования за тесты (CON-03); downstream-агентам при снятии Blocking необходимо работать с парой `(report-ts, id)` из раздела 8, а не с трекером issue.
