## 3. Конвенции проектирования

1. **Ноль исполняемых кейсов — обоснование.** Правило скилла и AGENTS.md: при вердикте FAIL без закрытых Blocking-вопросов исполняемые кейсы не проектируются; при CONDITIONAL — только для требований без открытых вопросов. Здесь таких требований нет (0 из 8), следовательно множество исполняемых кейсов пусто. Это не упущение покрытия, а прямое следствие качества требований.
2. **Одна заглушка на одно требование.** Объект трассировки — `requirement_id` из декомпозиции аудитора (R-1.1…R-3.1, AC-1). Документ-уровневые проблемы (GAP-04…GAP-07) не плодят отдельных сущностей: они перечислены полем `document_context_open_questions` внутри каждой заглушки (правило «одна проблема — одна запись» сохранено).
3. **Никаких выдуманных AC/шагов/ожиданий.** Каждая заглушка содержит только: причину блокировки (цитата + формулировка проблемы из отчёта), перечень «что НЕ проектируется до закрытия OQ», план действий после получения ответов.
4. **Тема.** Формат директивы `[TC] <название> (<тип>)` применим только исполняемым кейсам. Заглушка — не кейс, поэтому тема принята в формате существующей практики проекта: `[GAP] (#118) <requirement_id> — <предмет блокировки> (BLOCKED_BY_OPEN_QUESTION)`. Маркер статуса включён в тему, как у #142…#148.
5. **Трекер.** Все 8 заглушек — `Task (#2)`, а не `TestCase (#1)`: помещение не-кейса в трекер тест-кейсов исказило бы выборку «исполняемые кейсы» и нарушило правило «кейс без expected_result не создаётся».
6. **Иерархия/связи.** `parent_issue_id` и relations не передавались (директива п.5 и запрет изменения топологии без запроса). Связь с источником — текстом `related_requirement_issue: #118`.
7. **Приоритет (детерминированное правило).** Наличие ≥1 **Blocking**-блокера → `Critical (#3)`; блокеры только **Non-blocking** → `Major (#2)`. Основание — severity ведущей проблемы из §9/§10 review-report, а не субъективная оценка. Так `Minor (#1)` не используется: даже Non-blocking-вопрос в этом прогоне блокирует дизайн, что выше «незначительного».
8. **Предусловия.** Формально отсутствуют (GAP-07 → `PRECOND_DERIVED`), в заглушках как факт не используются; подтверждение требуется через OQ-12.
9. **Нумерация требований.** R-1.1…R-3.1 — временные ID аудитора (GAP-06 / OQ-11): у источника собственной нумерации нет, кроме AC-1. Зафиксировано в каждой заглушке, чтобы трассировка не выглядела официальной.
10. **Секции payload'а.** Единый каркас: машиночитаемые поля → `h2. Причина блокировки` → `h2. Что НЕ проектируется до закрытия OQ-xx` → `h2. Статус сущности` → `h2. План после закрытия вопроса`.
