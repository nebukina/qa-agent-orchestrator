## 2. Дедупликация и решение о переиспользовании (решающее отклонение прогона)

**Факт.** В проекте уже опубликован комплект тест-кейсов прошлого прогона той же цепочки (`report-ts=20261110-202304`): **TC-001…TC-014 → #88…#101**, **STUB-01…STUB-06 → #102…#107**. Проверка содержимого показала, что слоты `FR-001…FR-010` в том прогоне обозначали **те же** атомы текста #72, что и в настоящем отчёте (состав формы / `type=email` / `type=password` / `required` / кнопка / Шаг 1 / Шаг 2 / 200 / 401 / 500), а `AC-1…AC-4` — те же критерии источника.

**Следствие.** Слепое создание полного комплекта по новому отчёту дало бы **20 функциональных дублей**, что прямо нарушает QG3 (п.9 скилла: «Нет дублей существующих кейсов в Redmine»).

**Принятое правило.** Для каждой позиции настоящего прогона:
- **REUSE** — если существующий кейс уже реализует ровно то покрытие, которое разрешает Приложение B нового отчёта → новый issue **не создаётся**, на существующий issue кладётся трассировочная заметка с парой `(report-ts=20261110-225024, requirement_id)` и актуальными ссылками на OQ нового пространства имён.
- **NEW (ревизия)** — если expectation существующего кейса **противоречит** директивам нового отчёта (содержит ожидание из заблокированной зоны) → создаётся исправленная редакция, а на старый issue кладётся заметка `Superseded`.
- **NEW (новая позиция)** — если позиция в Redmine отсутствует.

**Материальная причина ревизий.** Новый отчёт перевёл «состояния кнопки и анти-двойной-сабмит» в заблокированную зону (FR-005, `GAP-05 / TEST-06 / OQ-12`). Кейсы #93, #95, #99, #101 прошлого прогона имели в `expected_result` утверждение **«отправлен ровно один POST-запрос (без дублей)»** — то есть проверяли анти-двойной-сабмит, ожидание которого нормативно не зафиксировано. По правилам конвейера такое ожидание изобретать запрещено → эти четыре позиции переизданы (#110, #111, #112, #113), старые отмечены `Superseded` (историческая запись прежнего прогона сохраняется, статусы не менялись).

| Позиция нового прогона | Решение | Redmine |
|---|---|---|
| 16 позиций (10 кейсов + 6 заглушек) | REUSE + заметка трассировки | #88, #89, #90, #91, #92, #94, #96, #97, #98, #100, #102, #103, #104, #105, #106, #107 |
| 4 позиции (ревизия ожидания) | NEW + `Superseded` на старом | новые #110/#111/#112/#113 ← старые #93/#95/#99/#101 |
| 1 позиция (STUB FR-007 контракт) | NEW (в прошлом прогоне отсутствовала) | #114 |

> Требуется подтверждение QA Lead: политика дедупликации между прогонами не задана (`OQ-24` / `GAP-19`) — решение принято агентом `test` самостоятельно и вынесено в Gaps (GAP-TD-12).
