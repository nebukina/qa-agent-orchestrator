## Детализация задач

### BLOCKED_BY_OPEN_QUESTION

#### #3 — REQ-2.1: Поля ввода (логин/email и пароль)
- **Причина:** Неясен формат поля «логин (или email)» — одно поле или два отдельных
- **Открытые вопросы:**
  1. Одно поле (логин/email) или два отдельных?
  2. Требования к валидации (длина, формат, обязательность)?
  3. Тип маскировки пароля?
  4. Подписи полей, плейсхолдеры, индикация обязательности?

#### #4 — REQ-2.4: Обработка ошибок
- **Причина:** Не специфицированы сообщения об ошибках
- **Открытые вопросы:**
  1. Тексты сообщений об ошибках для каждого сценария
  2. Расположение сообщений (inline/toast/модальное окно)
  3. Типы ошибок (валидационные, сетевые, серверные)

#### #2 — REQ-3.1: Производительность страницы логина
- **Причина:** Метрика «очень быстро» не определена
- **Открытые вопросы:**
  1. Конкретные метрики производительности (LCP, FID, TTFB)
  2. Целевые значения времени загрузки

### Полноценные задачи

#### #5 — REQ-2.2: Кнопка «Войти»
**Acceptance Criteria:**
1. Кнопка отображается под полями ввода логина и пароля
2. Состояния: Disabled (неактивна без заполнения), Default, Loading (спиннер + блокировка повторной отправки)
3. POST-запрос на endpoint аутентификации при нажатии
4. При успехе — редирект на главную страницу
5. При ошибке — отображение сообщения об ошибке
6. Блокировка повторной отправки до ответа сервера

#### #6 — REQ-2.3: Восстановление пароля
**Acceptance Criteria:**
1. Ссылка «Забыли пароль?» под формой входа
2. Переход на страницу восстановления пароля
3. Метод сброса: email-ссылка
4. Пользователь вводит email → письмо со ссылкой сброса
5. Ссылка действует ограниченное время (1 час)
6. После сброса можно войти с новым паролем
7. Ошибки: общее сообщение без раскрытия информации об аккаунте

#### #8 — REQ-2.5: Капча (защита от ботов)
**Acceptance Criteria:**
1. Капча после 3 неудачных попыток входа подряд
2. Тип: reCAPTCHA v2 или Cloudflare Turnstile (требует уточнения)
3. Отображение капчи перед/вместе с кнопкой «Войти»
4. Сброс счётчика после успешного входа
5. Счётчик привязан к IP-адресу и/или сессии
6. Капча не отображается при первом входе

#### #10 — REQ-3.2: Поддержка браузеров
**Acceptance Criteria:**
1. Поддержка: Chrome 100+, Firefox 100+, Safari 15+, Edge 100+, Яндекс.Браузер
2. Вёрстка не ломается в указанных браузерах
3. Все JS-функции работают во всех браузерах
4. Отсутствие ошибок в консоли браузера

#### #12 — REQ-3.3: Мобильная версия
**Acceptance Criteria:**
1. Responsive design под размеры экрана
2. Брейкпоинты: ≥1024px (десктоп), 768-1023px (планшет), <768px (мобильный)
3. Полноширинный вид полей и кнопки на мобильных
4. Touch-области min 44×44px
5. Клавиатура не перекрывает поля ввода
6. Скролл до активного поля при открытии клавиатуры

#### #11 — REQ-4.1: Блокировка после N неудачных попыток
**Acceptance Criteria:**
1. Блокировка после 5 неудачных попыток подряд в течение 15 минут
2. Длительность блокировки: 30 минут
3. Сообщение пользователю: «Аккаунт временно заблокирован. Попробуйте снова через 30 минут.»
4. Сброс счётчика после успешного входа или истечения временного окна
5. Блокировка не влияет на восстановление пароля

#### #9 — REQ-4.2: Функция «Запомнить меня»
**Acceptance Criteria:**
1. Чекбокс под полями ввода, над кнопкой «Войти»
2. При включении — сессия 30 дней, при выключении — session cookie
3. Механизм: httpOnly cookie с refresh token (JWT)
4. Не отключает капчу и не обходит блокировку
5. При блокировке аккаунта токен аннулируется

#### #7 — REQ-5: SSO интеграции
**Acceptance Criteria:**
1. Кнопки входа: Google, Yandex, VK
2. Протокол: OAuth 2.0 / OIDC
3. Редирект на главную страницу после авторизации
4. Создание локальной учётной записи при первом входе (по email)
5. Привязка SSO к существующей учётной записи
6. Обработка ошибок: отказ пользователя, ошибка провайдера, истечение токена
7. Кнопки SSO под основной формой входа
