### Epic: E-001 — Login Page
- **Summary:** Реализовать страницу авторизации (Login Page)
- **Description:** Разработка страницы входа в систему согласно требованиям (Confluence ID 720898). Включает форму ввода учетных данных, кнопку входа, сценарии успешного/неуспешного входа, валидацию, безопасность, адаптивность и accessibility.
- **requirement_id:** REQ-ALL
- **Size:** L

### Story 1: S-001 — Форма ввода учетных данных
- **Summary:** Реализовать поля ввода логина и пароля на странице авторизации
- **requirement_id:** REQ-2.1
- **Size:** M
- **Open Questions:** AMB-001 (Email vs Username), AMB-002 (точная длина пароля)

**Acceptance Criteria:**
- Given пользователь открыл страницу авторизации, When страница загружена, Then отображаются поля «Логин» и «Пароль» с соответствующими placeholder'ами
- Given поле «Логин», When пользователь вводит Email в формате user@domain.com, Then поле принимает значение без ошибки
- Given поле «Логин», When пользователь вводит значение длиной > 255 символов, Then отображается ошибка валидации
- Given поле «Пароль», When пользователь вводит текст, Then символы маскируются (отображаются как ●)
- Given поле «Пароль», When пользователь нажимает иконку «глаз», Then символы отображаются в явном виде
- Given поле «Пароль», When пользователь вводит пароль короче 8 символов, Then отображается ошибка «Пароль слишком короткий»
- Given поле «Пароль», When пользователь вводит пароль длиннее 64 символов, Then отображается ошибка «Пароль слишком длинный»

### Story 2: S-002 — Кнопка входа и состояния
- **Summary:** Реализовать кнопку «Войти» с обработкой состояний
- **requirement_id:** REQ-2.2
- **Size:** M
- **✅ UX-концепция выбрана:** Кнопка активна всегда, при пустых/невалидных полях выдаёт ошибку валидации при нажатии

**Acceptance Criteria:**
- Given форма входа, When пользователь нажимает «Войти» с пустыми или невалидными полями, Then кнопка НЕ блокируется, но под каждым полем отображается сообщение об ошибке валидации
- Given пользователь нажал кнопку «Войти», When все поля валидны и запрос отправлен на сервер, Then кнопка блокируется и отображает спиннер
- Given кнопка в состоянии загрузки, When пользователь пытается нажать её повторно, Then повторная отправка формы блокируется (Double Submit Prevention)

#### Task: T-003 — Реализовать кнопку «Войти» и состояния
- **Parent:** S-002
- **Description:** Кнопка с обработкой disabled/активного состояния, индикатором загрузки, защитой от Double Submit
- **requirement_id:** REQ-2.2
- **Size:** S

### Story 3: S-003 — Сценарии входа пользователя
- **Summary:** Реализовать сценарии успешного и неуспешного входа, ссылки восстановления и регистрации
- **requirement_id:** REQ-2.3
- **Size:** M
- **Open Questions:** AMB-003 (куда редиректить после входа)

**Acceptance Criteria:**
- Given пользователь ввёл корректные данные, When он нажимает «Войти», Then происходит редирект в личный кабинет (или на предыдущую страницу)
- Given пользователь ввёл неверный логин или пароль, When он нажимает «Войти», Then отображается общее сообщение «Неверный логин или пароль» (без уточнения поля)
- Given неудачная попытка входа, When страница обновлена, Then поле «Пароль» пустое, поле «Логин» сохраняет введённое значение
- Given страница входа, When пользователь видит форму, Then отображается ссылка «Забыли пароль?»
- Given страница входа, When пользователь видит форму, Then отображается ссылка «Нет аккаунта? Зарегистрироваться»

### Story 5: S-005 — Валидация и обработка ошибок
- **Summary:** Реализовать клиентскую и серверную валидацию, rate limiting
- **requirement_id:** REQ-3
- **Size:** L
- **Open Questions:** AMB-004 (blur vs submit валидация), AMB-005 (таймаут), AMB-006 (N для rate limiting), CON-002 (CAPTCHA vs блокировка)

**Acceptance Criteria:**
- Given поле формы, When поле теряет фокус (blur) с пустым/невалидным значением, Then поле подсвечивается красным и отображается текст ошибки под полем
- Given сервер вернул ошибку 500/502/503, When пользователь отправил форму, Then отображается сообщение «Сервис временно недоступен, попробуйте позже»
- Given сервер не отвечает (таймаут), When пользователь отправил форму, Then отображается соответствующее сообщение
- Given пользователь совершил N неудачных попыток входа, When N превышено, Then включается CAPTCHA или временная блокировка

### Story 6: S-006 — Безопасность
- **Summary:** Реализовать требования безопасности: HTTPS, CSRF, хеширование паролей
- **requirement_id:** REQ-4.1
- **Size:** L

**Acceptance Criteria:**
- Given страница авторизации, When пользователь открывает её, Then соединение используется только по HTTPS
- Given форма авторизации, When данные отправляются, Then пароль передаётся только методом POST
- Given форма авторизации, When страница загружена, Then присутствует CSRF-токен
- Given пароль пользователя, When он сохраняется на сервере, Then пароль хранится в виде хеша с солью (bcrypt/argon2)
- Given пользовательский ввод, When данные обрабатываются, Then все поля экранируются от SQL-инъекций и XSS

#### Task: T-013 — Реализовать CSRF-защиту
- **Parent:** S-006
- **Description:** CSRF-токен для формы авторизации
- **requirement_id:** REQ-4.1
- **Size:** S

#### Task: T-014 — Реализовать безопасную передачу и хранение паролей
- **Parent:** S-006
- **Description:** POST-отправка, HTTPS, хеширование bcrypt/argon2, экранирование ввода
