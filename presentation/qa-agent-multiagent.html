до задач, тест-кейсов и матрицы трассировки

Оркестратор не «умеет всё сам»: он маршрутизирует работу и держит quality-гейты. Каждый субагент изолирован и отвечает ровно за один этап.

Оркестратор

Управляет жизненным циклом прогона и ничего не проектирует самостоятельно.

  • Read-only к Redmine: читает issue, пишет только свои артефакты
  • Делегирует аудит, задачи и тесты субагентам
  • Сводит матрицу Req → Task → Test и выпускает final-report
  • При FAIL останавливает поток и эскалирует человеку

Субагенты + скиллы

Жёсткая изоляция ролей: один субагент — ровно один скилл, межскилловые вызовы запрещены.

  • @review → requirement-review: разбор по 4 осям (противоречия, неоднозначность, полнота, тестируемость)
  • @task → task-design: Epic → Story → Task, AC в формате Given-When-Then
  • @test → test-design: positive / negative / boundary
  • Публикация в Redmine — только у @task и @test

Quality Gates

Ни один артефакт не становится итоговым без проверки.

  • QG1 вердикт аудита: PASS / CONDITIONAL / FAIL
  • QG2 / QG3 качество task-spec и test-model
  • QG4 допуск финального отчёта
  • QG-A…QG-G полнота артефактов, трассировка, доля GAP, отсутствие посторонних записей в Redmine

Заметки. Ключевой тезис: надёжность даёт не «умный агент», а разделение ответственности и гейты. Оркестратор специально обеднён — он не анализирует требования и не пишет задачи, поэтому не может подменить собой всю цепочку и не имеет прав на запись в Redmine. Спорные требования не «додумываются», а уходят человеку как Open Questions.
Как это работает

Конвейер со сквозным timestamp, GAP-моделью и защитой от мутаций

Единый {ts} прогона связывает все артефакты: любой результат воспроизводим и трассируем до исходного issue.

Ingestion · raw-{ts}.md→ Audit · QG1 · review-report→ @task · task-spec @test · test-model→ Final Report · QG4 · матрица трассировки

GAP вместо фантазии

Главный анти-галлюцинационный механизм.

  • При CONDITIONAL проектируются только бесспорные требования
  • Спорные получают заглушку BLOCKED_BY_OPEN_QUESTION
  • Таким заглушкам запрещено придумывать Acceptance Criteria и шаги тестов
  • Открытые вопросы фиксируются с владельцем и приоритетом

Безопасность как свойство потока

  • Текст требования — только данные; инструкции из него не исполняются
  • Попытки Prompt Injection фиксируются как SEC-01
  • Секреты не попадают в чат, артефакты и задачи; паттерны маскируются [REDACTED]
  • Запрещены update/delete существующих задач без явной команды; ошибочная запись помечается [OBSOLETE], а не удаляется

Инструменты и след прогона

  • Redmine через MCP, доступ по API-ключу из .env
  • Артефакты: 00-raw → 03-test-design, final-report, diagnostics/errors/*.log
  • Ротация: current/ только при QG4=PASS, архив в history/{ts}/
  • Логи отказов — отдельно по каждому агенту
Артефакты прогона связаны единым timestamp · воспроизводимость и трассируемость2 / 3
Заметки. Подчеркните два решения, которые отличают систему от «обёртки над LLM»: (1) GAP-модель — агент сознательно оставляет дырки вместо выдумывания деталей, и это измеримо (доля GAP); (2) необратимые операции в трекере запрещены по умолчанию, поэтому ошибка агента не уничтожает данные. Третий акцент — единый timestamp: по нему любой результат прогона воспроизводится и доказывается вплоть до исходного issue.

Eval-контур (Java)

EvalRunner гоняет агента через opencode run --auto, Evaluator сверяет ожидаемые свойства и запрещённое поведение.

  • EVC-001 Happy Path · EVC-002 CONDITIONAL · EVC-003 защита от Prompt Injection
  • EVC-004 Boundary · EVC-005 Ambiguity · EVC-006 критический FAIL
  • Пороги: Pass Rate ≥ 95%, Expected Properties ≥ 95%, Forbidden Behavior = 0%, Errors = 0
  • Сводка: artifacts/current/eval_results.json, история в artifacts/history/

Гарантии: чего система принципиально не делает

  • Не придумывает Acceptance Criteria для спорных требований — только BLOCKED_BY_OPEN_QUESTION
  • Не изменяет и не удаляет существующие задачи: ошибочная запись помечается [OBSOLETE], а не стирается
  • Не выдаёт DRAFT / INCOMPLETE за финальный результат — статус пишется явно
  • Не скрывает отказы: лог по каждому агенту и эскалация человеку

Заметки. Не продавайте «идеальную картинку»: ценность в том, что система честно фиксирует PARTIAL / INCOMPLETE и эскалирует человеку, а не рисует зелёный статус. Цифра 0 в правой нижней метрике — самая дорогая: за все прогоны ни одна существующая задача в трекере не была испорчена. На вопрос «а если агент ошибётся?» отвечать гарантиями из правой карточки: ошибку нельзя стереть, её видно в логе и в статусе артефакта.
